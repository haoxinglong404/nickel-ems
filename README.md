## 一、这是什么

一个跑在生产现场的设备管理 Web 应用，**5 个车间共用一套系统**，覆盖设备台账、日常点检、检修记录、备件二级库、润滑管理五件事。

- **生产状态**：点检模块每天在用，`inspectmonthly` 集合持续写入 —— **系统中断即影响车间点检记录**

## 三、功能模块

底部导航七项（高压酸浸车间可见全部，其余车间只有前两项和最后一项）：

1. **重点设备看板** —— 高压釜给料泵／搅拌器／预热器给料泵三组重点设备的零件更换台账：在用天数、平均寿命、超寿命预警、本月／本季度零件消耗、分厂家寿命对比。**全员只读**。
2. **设备台账** —— 989 台设备的位号、名称、规格、铭牌、A/B/C 关键性等级；支持搜索、区域／类型／等级筛选；详情页含「相关检修记录」「润滑点」两个子页。
3. **点检** —— 核心模块。79 个点检模板（数值型 + 勾选型），按 A/B/C 等级决定频次（A=1 天／B=2 天／C=7 天，再与模板自身周期取较小值）。数值超限强制填写备注，一台设备一个月一张月表（`inspectmonthly`），同一天重复提交即覆盖当天（作为订正通道）。带趋势图。
4. **检修记录** —— 故障抢修／计划检修／预防性维护三类；可选二级库备件，**选二级库备件会自动扣减库存**，手填的不扣。仅管理员可登记／编辑／作废；**无彻底删除**，只能作废（可恢复，作废时库存自动回补）。附「当个事儿办」缓办事项清单。
5. **二级库** —— 现场库存台账，带结存的完整出入库账。领用／入库／撤销／硬删除双轨制。
6. **润滑** —— 896 个润滑点，按脂／油／待补油号三类分组，按设备分组卡片支持「一键登记全部」；含免维护点识别、到期与逾期统计、五定表导出。
7. **我的** —— 语言切换、切换车间、账号管理、修改密码。

### 语言

界面支持**中文／印尼语**切换（`localStorage` 里的 `ems_lang_v01`，切换即刷新页面）。译文以「中文原文作 key」的字典 + DOM 出口统一翻译实现，**写入数据库的永远是中文原文**，两种语言的用户共用同一份数据。字典未收录的内容原样显示中文。

新增印尼语词条：在 `index.html` 里搜 `Object.assign(I18N_ID` ，往对应的那一段加一行即可。**新增第三种语言**：往 `LANGS` 加一个 key + 一段字典。

## 五、技术约定（改代码前必读）

这四条不是风格偏好，破坏其中任何一条都会打断现场的工作流：

### 1. 不引入任何构建工具

不用 webpack、vite，不 `npm install` 任何东西。项目就是一个 `index.html`，浏览器直接打开就能跑。

### 2. 不拆分文件

CSS 和 JS 必须留在 `index.html` 里。**部署方式是直接上传／提交这一个文件** —— 这是使用者的核心工作流。

### 3. 不修改已有字段名

Firestore 里已有大量历史数据，下列字段名改一个字就会让历史记录读不出来：

| 集合 | 字段 | 含义 |
|---|---|---|
| `lubepoints` | `operationType` | `oil` 油 / `grease` 脂（但界面分类看 `standardOil` 是否含"脂"） |
| `lubepoints` | `maintenanceFree` | `true` = 免维护，不计入逾期统计 |
| `secondstockhistory` | `type` | `in` 入库 / `out` 领用 |
| `secondstockhistory` | `reverted` / `isCounter` | 撤销双轨标记 |
| `secondstockhistory` | `mlId` | 检修记录的账本投影，带此字段的记录禁止手动撤销／删除 |
| `maintenancelogs` | `category` | `fault` / `planned` / `preventive` |
| `maintenancelogs` | `deleted` | 作废（软删除）标记 |
| `maintenancelogs` | `noReplace` | `true` = 本次只维修未换新件，寿命统计跳过 |
| `equipments` | `abcClass` | `''` / `A` / `B` / `C` 关键性等级 |
| `equipments` | `noInspect` / `inspectTplKey` | 不进点检 / 指定点检模板 |
| 全部业务集合 | `plant` | 车间归属，缺省视为 `hpal` |
| `equipments`·`inspectmonthly`·`inspecthistory` | `alsoPlants` | 跨车间借用：归属不变，但列出的车间也能看到并点检 |

### 4. 业务数据只能存在 Firestore

`localStorage` 只用来存会话与偏好，一共六个 key：会话 token（`ems_session_v06`）、上次登录账号的快照（`ems_user_v01`，只含工号／姓名／角色，无密码，用于秒进应用）、当前车间（`ems_plant_v01`）、界面语言（`ems_lang_v01`），以及两个网络降级标记（`ems_idb_bad_v01`／`ems_net_degrade_v01`，手机浏览器兼容性兜底用）。**任何业务数据都不许存本地。**

### 另外两条

- **`onclick` 调用的函数必须挂到 `window` 上**（`window.fn = fn`），否则模块作用域里的函数点了没反应。
- **首次启动的种子函数不要删**（`seedIfEmpty` / `seedLubeIfEmpty` / `seedInspectionTemplatesIfEmpty` / `seedSecondStockIfEmpty`）—— 它们只在云端对应集合为空时才写入，是幂等安全的灾备。

### 位号命名规则

格式 `{区域}-{专业}-{类型}-{序号}{分支}`，例如 `201-PE-AG-001A`（201 区域·工艺设备·搅拌器·001·A 分支）、`316-1-MT-PP-003`。**新增设备的位号必须符合这个格式**，拿不准就照 `equipments` 集合里现有的写。

> **每个文档的 `id` 字段必须和 Firestore 的文档 id 一致** —— 代码多处依赖这个约定。

### 安全现状（重要，务必读完）

规则文件是 `firestore.rules`，当前模型是**匿名认证 + 集合白名单**：

- 应用启动时执行 `signInAnonymously()`，任何访问者都会自动获得一个匿名身份
- 白名单内的 17 个集合，**任何已通过匿名认证的客户端都能读写**
- 白名单外的一切路径一律拒绝

**这意味着**：能打开这个网页的人，理论上就能读写全部业务数据。前面第四节那张权限表是界面层拦截，**服务器不强制**。目前挡住外部站点的第二道门是 Google Cloud 上给 API Key 配的 **HTTP Referrer 白名单**（只允许指定域名调用）。

站点若为公开仓库发布的 GitHub Pages，则是**公网可访问**的。若要加固，可以考虑的方向（未实施）：把角色权限下沉到规则层、`users` 集合仅管理员可写、加硬删除审计字段。

**修改规则的两条铁律**：

1. 新增集合必须同步更新 `firestore.rules` 并**在 Firebase 控制台手动发布**（改文件不会自动生效）
2. **重新发布规则时必须包含 `meta` 集合** —— 漏了它，应用启动时读迁移标记会被拒绝，`init()` 中断，界面表现为「设备台账 0 台 / 云端连接失败」

### 用量配额

免费 Spark 方案的额度是 **每天读 50,000 次、写 20,000 次**（读和写是两个独立的桶），**重置时间为美国太平洋时间零点**（印尼时间下午 3 点，夏令时下午 4 点）。控制台显示的「过去 24 小时」是滚动窗口，不等于当日已用量。

计费按**服务器返回的文档份数**算，空结果也最低记 1 次读。系统已做过读取量优化（按需订阅、按车间服务端过滤、润滑历史只订近 90 天），目前**冷启动约 320～440 次读**。

- 页面**开着**的时候几乎不花额度（只按变化的文档计费）
- **关掉再重新打开最贵**；监听断开超过 30 分钟再重连，按全新查询计费
- 给车间的应急话术：**点检期间别刷新、别关页面**（额度读爆时，已打开的客户端仍能提交，只有新开或刷新的进不去）

若要升级到 Blaze 按量付费方案，**务必同时设置预算告警和 Firestore 每日读取上限**，否则异常流量会产生真实账单。

## 七、本地运行

项目无构建步骤，起一个静态服务器即可：

```bash
python -m http.server 8000
```

然后打开 **http://localhost:8000/?preview=1**

### 端口必须是 8000

Firebase 的 API Key 域名白名单**精确到含端口的地址**。`localhost:8000` 在白名单里，换成别的端口会直接报 `requests-from-referer-...-are-blocked`，匿名认证 403、应用启动中断、界面弹「云端连接失败」。

同理，**直接双击 `index.html` 用 `file://` 打开也会被挡**（没有 referer）。必须走 http 服务器。

`?preview=1` 是预览模式：设备台账的显示字段会用文件内置的种子数据覆盖云端，方便离线看界面。**注意它连的仍然是生产数据库** —— 预览模式下做的写操作是真写云端。

> 改完代码看不到变化，先怀疑浏览器缓存：网址后面加个 `?v=随便改个数`。

### 换到新的托管地址后，必须做这一步

Firebase 的 API Key 域名白名单里如果没有新地址，**新站点会打不开**（匿名认证 403）。

1. 打开 Google Cloud Console → APIs & Services → Credentials
2. 找到这个项目的浏览器 API Key
3. 在 **HTTP referrers（网站）** 限制列表里加上新的站点地址，例如 `https://<账号>.github.io/*`
4. 保存，等一两分钟生效

> 免费个人 GitHub 账号的 Pages 只能从**公开仓库**发布。私有仓库发 Pages 需要付费方案。若继续用公开仓库，站点即为公网可访问，包含设备台账与点检数据。

| 新开页面进不去，已开着的能用 | 当天读取额度用满了，等太平洋时间零点重置 |
| 登录按钮点了没反应 | 某个 `onclick` 的函数没挂到 `window` 上；看浏览器控制台报错 |
| 手机上一直「连接中…」不动 | iOS Safari 的 IndexedDB 挂起问题，代码已有降级兜底；登录页有诊断行显示卡在哪一步 |

## 十、设计规范

改界面时请沿用现有的 CSS 变量，不要写内联的颜色值。

```css
--paper:    #FAFAF7   /* 米白背景 */
--ink:      #1A2A1A   /* 墨绿·正文 */
--g-deep:   #3A5424   /* 镍钴绿·深（主色） */
--g-forest: #27500A   /* 镍钴绿·森林 */
--g-mist:   #F0F5E8   /* 镍钴绿·雾 */
--g-primary:#97C459   /* 镍钴绿·亮 */
--muted:    #6B6A66   /* 次级文字 */
--subtle:   #9B9A96   /* 辅助文字 */
--line:     #E4E0D8   /* 分隔线 */
```

- **字体**：Cormorant Garamond（大标题）/ Inter（正文按钮）/ JetBrains Mono（标签数字）
- **圆角**：主卡片 14px，次级 10px，胶囊按钮 999px
- **间距**：8px 网格
- **移动端硬指标**：按钮不小于 44px、输入框不小于 52px、字号不小于 13px
